# 数据格式对比与训练影响分析

---

## 一、三种数据格式对比

### 1.1 真实 LOBSTER 逐笔数据

LOBSTER 是典型的美股 Level-3 逐笔数据，包含订单簿上的**每一次变化**：

| 消息类型 | 含义 | 占比（典型） |
|---------|------|------------|
| **type-1** | 新限价单提交 | **60-70%** |
| **type-2** | 撤单（部分或全部） | **20-30%** |
| **type-4** | 成交 | **5-10%** |
| 其他 | 隐藏单、拍卖等 | <1% |

```
真实市场:
时间 → 下单  → 下单  → 撤单  → 成交  → 下单  → 撤单  → ...
        深度+1    深度+1    深度-1    深度-1    深度+1    深度-1
```

**深度在动态平衡中波动。** 每秒几十到几百次订单变化，深度围绕均值波动。

### 1.2 A 股逐笔成交 + 快照数据（我们用的格式）

我们的转换脚本 `convert_snapshot_trade_to_lobster.py` 将两个 CSV 合并：

| 数据列 | 来源 | 说明 |
|--------|------|------|
| 快照 CSV | 每 ~3 秒一张订单簿 10 档快照 | 原始 LOBSTER 没有这个 |
| 成交 CSV | 逐笔成交（TradeBSFlag 1/2） | 原始 LOBSTER type-4 子集 |

转换后的格式：

| 事件类型 | 来源 | 含义 | 占比（300059） |
|---------|------|------|--------------|
| **type-1** | 快照标记 | qty=0, price=0 伪事件 | **26%** |
| **type-4** | 成交 | 真实成交 | **74%** |
| type-2/3 | — | **不存在** | **0%** |

```
我们的数据:
时间 快照  →  成交  成交  成交  →  快照  →  成交  →  快照
        深度=真实          深度衰减      深度重置    深度衰减

两快照之间: 只有成交消耗深度，没有订单补充深度
```

### 1.3 关键差异矩阵

| 维度 | 真实 LOBSTER | 我们的转换数据 | 影响 |
|------|-------------|--------------|------|
| **总消息量/天** | 200K-500K | **35K-50K** | ❌ 少 5-10 倍 |
| **限价单 (type-1)** | 实际订单 60-70% | **伪事件 (qty=0)** | ❌ 没有真实订单流 |
| **撤单 (type-2)** | 20-30% 有真实撤单 | **0%** | ❌ 深度只减不增 |
| **成交 (type-4)** | 5-10% | **74%** | ❌ 成交占比异常高 |
| **订单流方向** | 双边（买卖挂单） | **单边（只有成交）** | ❌ 缺乏供应侧行为 |
| **时间精度** | 纳秒 | **毫秒** | 🟡 精度足够 |
| **价格精度** | tick 级别 | tick 级别 | ✅ 正确 |
| **深度信息** | 全部深度 | **10 档快照** | 🟡 足够 |

### 1.4 可视化对比

```
真实 LOBSTER 一段 3 秒窗口:
  🟢下单  🟢下单  🔴撤单  🟢下单  💥成交  🔴撤单  🟢下单  💥成交
  深度:7    深度:8    深度:7    深度:8    深度:7    深度:6    深度:7    深度:6
                       ↕ 深度在 6-8 之间波动

我们的数据 3 秒窗口:
  📷快照  💥成交  💥成交  💥成交  💥成交  📷快照  💥成交  💥成交
  深度:7    深度:6    深度:5    深度:4    深度:3    深度:7    深度:6    深度:5
             ↕ 深度从 7 单调下降到 3，然后被快照重置到 7
```

## 二、对训练结果的具体影响

### 2.1 做市商（MM）受影响最大

| 能力 | 真实数据下 | 我们的数据下 | 结论 |
|------|----------|------------|------|
| **报价策略** | 订单流不断，可反复撤重挂 | 深度持续衰减，报价机会减少 | ❌ 高估 MM 策略价值 |
| **库存管理** | 新订单随时出现消化库存 | 只有成交消耗，库存难对冲 | ❌ MM 风险更高 |
| **面对撤单** | 对手方随时可能撤单 | 对手从不撤单 | ❌ MM 不用学应对撤单 |
| **对抗 EXE** | EXE 可以吃其他人的单 | EXE 只能吃 MM 的单 | ❌ MM 被 EXE 针对严重 |

**最关键的发现：** Phase 1 MM Only 能跑出 +0.038 正收益，但加入 EXE 后直接掉到 -0.0007。这在我们数据格式下被放大了——因为 EXE 没有其他对手单可吃，只能吃 MM 的。在真实数据下，EXE 有更广泛的对手方，MM 的压力会减轻很多。

### 2.2 执行端（EXE）受数据影响较小

| 能力 | 真实数据下 | 我们的数据下 | 结论 |
|------|----------|------------|------|
| **基本执行** | 可以吃限价单 | 可以吃限价单 | ✅ 都行 |
| **选择对手** | 多个做市商+散户 | **只有 MM** | ❌ EXE 的选择空间小 |
| **滑点估算** | 价格由市场决定 | 价格由 MM 报价决定 | ❌ 滑点可能被扭曲 |

### 2.3 双 agent 训练：数据缺陷让问题更严重

```
真实数据下的双 agent:
  MM ↔ EXE ↔ 市场背景订单流(60-70% 消息)
         ↕
  EXE 可以吃 MM 的单，也可以吃背景订单
  MM 的持仓风险被背景订单流分散

我们数据下的双 agent:
  MM ↔ EXE（几乎一对一对抗）
         ↕
  EXE 只能吃 MM 的单（没有其他选择）
  MM 的持仓风险只能自己扛（没有新订单补充深度）
```

所以 Phase 2 中 MM 从 +0.038 跌到 -0.0007 是**数据缺陷的放大效应**。在真实数据下，MM 的 drop 应该小很多。

## 三、Phase 1 和 Phase 2 结果的再解读

### 3.1 Phase 1 MM Only = +0.038

```
这个结果相对可靠。
因为没有 EXE 吃单，MM 面对的是历史数据中的成交。
虽然缺少订单补充，但 MM 报出合理价格后，被成交吃掉≈正常。
```

### 3.2 Phase 2 MM+EXE = MM 掉到 -0.0007

```
这个结果被数据缺陷严重放大。
EXE 只能吃 MM 的单 → MM 被针对 → MM 策略崩溃。
在真实数据下，EXE 有其他对手方，MM 不会跌这么多。
```

### 3.3 原始同时训练 v2 = 双 agent 都差

```
MM 和 EXE 同时在学，互相干扰。
加上数据缺陷（EXE 只能吃 MM），恶性循环。
```

## 四、数据问题优先级

| 问题 | 严重度 | 修复难度 | 建议 |
|------|--------|---------|------|
| **缺撤单和新限价单** | 🔴 最高 | 🔴 需要新数据源 | 用 AMZN 测试或找 A 股逐笔委托 |
| **消息量太少（35K vs 300K）** | 🟡 中 | 🔴 需要新数据源 | 随新数据源自动解决 |
| **type-1 伪事件 (qty=0)** | 🟢 低 | 🟢 修改转换脚本 | type-1 目前被忽略，无害但迷惑 |
| **快照仅 10 档深度** | 🟢 低 | 🔴 取决于数据源 | 10 档够做市了 |

## 五、验证思路

如果可以拿到 A 股逐笔委托数据，或直接切到 AMZN LOBSTER 数据，应该：

1. **用真实数据跑一轮 Phase 1（MM Only）** → 看 MM 在完整订单流下能否盈利
2. **用真实数据跑一轮同时训练（MM+EXE）** → 看双 agent 在真实环境下是否不再零和

如果真实数据下 MM+EXE 同时训练也能让 MM 保持正收益，那"数据缺陷导致零和"的假设就成立了。

## 六、总结

| 问题 | 答案 |
|------|------|
| 我们的数据和 LOBSTER 差在哪？ | **缺撤单和新限价单**，消息量少 5-10 倍 |
| 这影响什么？ | **深度只减不增，EXE 只能吃 MM 的单** |
| Phase 1 结果可信吗？ | ✅ 相对可靠 |
| Phase 2 结果可信吗？ | ❌ 被数据缺陷放大 10 倍 |
| 背景 agent 能解决吗？ | ❌ 解决不了，随机噪音不是真实订单流 |
| 最好的解决方案？ | **换数据源**（A 股逐笔委托或 AMZN LOBSTER） |
